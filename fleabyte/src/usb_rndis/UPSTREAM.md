TinyUSB RNDIS driver and reports from https://github.com/hathach/tinyusb/tree/c391fe9cb05abea9058ea3fc781c64e11bd057ab.

MIT licensed; original notices are retained. The application driver uses private symbol names so it coexists with Arduino's compiled-in NCM driver. Local changes validate USB messages, enlarge the bounded control buffer, accept larger host response buffers, recover failed transfers, preserve the packet filter on a non-addressing reset and expose link/filter, controller-reset and transmit-result callbacks to the hotspot plugin.

RNDIS IN messages use one endpoint-sized USB packet per controller request, retaining message ownership until the final short packet completes. Full packets continue the same host bulk transfer. Microsoft's permitted one-byte zero terminator is appended when the message is an exact endpoint-size multiple; `MessageLength` excludes that byte. An initial rejected submission returns failure so the caller retains its queued frame. A rejected continuation retains the message and retries the same offset from the USB task. Reset/deinit clears pending continuations. ECM retains its upstream whole-message transfer behavior. `USB_IN_PROGRESS` records total bytes, completed bytes, active chunk and pending retry.

This is a candidate workaround for an observed ESP32-S3 multi-packet IN transfer that stopped completing, not a demonstrated fix for a known controller defect. Native tests cover message assembly and ownership, but hardware stability and throughput still require validation. It does not replace or patch installed framework files.
